# 1、从 `claude` 命令到 Agent 主循环

当我们在终端中输入：

```sh
claude
```

表面上只是启动了一个命令行程序，背后却完成了一系列准备工作：解析参数、
读取配置、恢复会话、组装上下文、请求模型，并根据模型返回的内容执行工具。
这些步骤最终汇聚成 Agent 的核心——主循环。

> 本文描述的是便于理解 Agent 工作方式的概念模型，重点在整体流程，而不是某个
> 版本的私有实现细节。

## 整体流程

一次典型的 Claude Code 会话可以简化为：

```text
claude 命令
    │
    ▼
解析命令行参数
    │
    ▼
加载配置与项目上下文
    │
    ▼
创建或恢复会话
    │
    ▼
等待用户输入
    │
    ▼
组装发送给模型的消息
    │
    ▼
调用模型
    │
    ├── 返回普通文本 ──────────────┐
    │                              │
    └── 请求调用工具               │
             │                     │
             ▼                     │
        执行工具并收集结果           │
             │                     │
             └── 再次调用模型 ◀─────┘
                         │
                         ▼
                    输出最终回答
```

其中最值得关注的是最后几步：模型不只是生成文本，还可以请求执行工具；工具结果
会被追加到上下文中，再交给模型继续判断。这个过程反复进行，就形成了 Agent 主循环。

## 1. 命令入口

Shell 找到 `claude` 可执行程序后，会把命令行参数和当前运行环境交给它。例如：

```sh
claude
claude "解释这个项目"
claude --continue
```

不同参数决定程序采用哪种启动方式：

- 进入交互式会话；
- 带着初始问题直接开始任务；
- 恢复之前的会话；
- 启用或覆盖某些运行配置。

这一层的任务主要是把用户输入转换为程序内部可以使用的启动参数，然后进入真正的
应用初始化阶段。

## 2. 加载配置

Agent 在开始工作前，需要知道自己可以做什么，以及应该遵守哪些约束。初始化阶段
通常会收集以下信息：

- 用户级配置；
- 项目级配置；
- 当前工作目录；
- 可用工具及其权限；
- 模型与运行参数；
- 项目说明文件；
- 环境变量和终端能力。

这些信息不会被简单拼成一大段文本。程序会区分系统规则、项目规则、历史消息和
当前用户输入，并按照各自的优先级组织它们。

## 3. 创建会话

会话负责保存一次连续交互所需的状态，常见内容包括：

- 用户和模型的历史消息；
- 已执行的工具调用及结果；
- 当前任务状态；
- token 使用情况；
- 工作目录和权限状态。

如果是全新会话，程序会创建空的消息历史；如果是继续会话，则会恢复之前保存的
记录。对模型而言，每一次请求仍然是一次独立调用，连续对话的感觉来自客户端不断
携带必要的历史上下文。

## 4. 组装模型输入

用户输入问题后，客户端会准备一次模型请求。概念上可以理解为：

```text
模型输入 =
    系统指令
  + 项目指令
  + 可用工具定义
  + 精选的会话历史
  + 最新的用户消息
  + 必要的运行环境信息
```

这里的“精选”很重要。会话越来越长时，不可能无限制地把所有内容原样发送给模型，
因此系统可能需要裁剪、压缩或总结较早的上下文，把有限的上下文窗口留给当前任务。

## 5. 模型决定下一步

模型收到上下文后，会预测当前最合适的下一步。返回结果通常可以归为两类。

### 直接回复

如果已有信息足以回答，模型会生成文本。客户端把文本显示到终端，本轮交互结束。

### 请求调用工具

如果还需要查看文件、搜索代码或执行命令，模型会返回结构化的工具调用请求。它通常
包含：

- 工具名称；
- 调用参数；
- 可选的解释信息。

模型本身不会直接操作文件或终端。真正的执行由 Claude Code 客户端负责，这使得
权限检查、沙箱限制和用户确认都可以发生在模型与系统之间。

## 6. 执行工具

客户端收到工具调用请求后，大致会经历以下步骤：

1. 验证工具是否存在；
2. 检查参数是否合法；
3. 判断当前权限是否允许；
4. 必要时请求用户确认；
5. 执行工具；
6. 收集标准输出、错误信息和退出状态；
7. 把结果作为新的消息加入会话。

工具结果并不是最终答案。它是模型在下一轮推理时可以使用的新证据。

例如，模型为了理解项目可能先读取目录，再打开某个配置文件，接着运行测试。每次
工具调用都会让它获得更多环境反馈，从而逐步缩小问题范围。

## 7. Agent 主循环

把前面的步骤组合起来，就得到一个简化的主循环：

```ts
while (!session.finished) {
  const input = buildModelInput(session)
  const response = await callModel(input)

  if (response.type === 'tool_use') {
    const result = await executeTool(response.tool)
    session.messages.push(response, result)
    continue
  }

  session.messages.push(response)
  renderToTerminal(response)
  session.finished = true
}
```

真实系统会处理流式输出、多个工具调用、取消操作、权限确认、错误恢复和上下文压缩，
但核心结构没有改变：

> 模型观察当前状态，选择一个动作；环境执行动作并返回结果；模型根据新状态继续
> 决策，直到能够给出最终回答。

这也是 Agent 与普通聊天模型最关键的区别。普通聊天通常是“一次输入、一次输出”，
而 Agent 会在一个任务中经历多轮“思考—行动—观察”。

## 8. 主循环何时结束

常见的退出条件包括：

- 模型返回最终文本，不再请求工具；
- 用户主动取消；
- 工具执行遇到无法恢复的错误；
- 权限请求被拒绝；
- 达到运行时间、调用次数或 token 限制；
- 客户端判断任务已经完成。

退出主循环不一定意味着整个会话结束。客户端仍可以继续等待下一条用户消息，并以
现有会话状态开启新一轮 Agent 循环。

## 小结

从 `claude` 命令到 Agent 主循环，可以记住四个关键阶段：

1. **启动**：解析参数并加载运行环境；
2. **建会话**：恢复历史，准备上下文；
3. **做决策**：模型选择回复或调用工具；
4. **跑循环**：执行工具、反馈结果，直到任务结束。

理解这个循环之后，许多现象都会变得直观：为什么 Agent 需要权限确认，为什么工具
结果会影响下一步，以及为什么长任务会经历多次模型调用。
